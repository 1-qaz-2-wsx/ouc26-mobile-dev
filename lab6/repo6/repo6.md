## 一、实验内容

### 1. 实验目标与开发环境

本实验使用微信小程序原生框架和微信云开发能力，完成一个图片分享社区 `cloudPhoto`。项目综合使用云数据库、云存储和云函数，实现图片上传、图片流展示、作者主页、图片详情、图片保存、分享、照片删除和会话退出等功能。

在教材基础功能的基础上，项目进一步完善了分页加载、下拉刷新、搜索、关注、点赞、收藏、评论、上传进度、空状态、错误重试、照片删除、退出登录和孤立云文件清理等交互。主要练习内容包括：

- 使用 `wx.cloud.init()` 初始化云开发环境；
- 使用云数据库 `photos` 集合保存图片元信息；
- 使用云存储上传、下载和清理用户图片；
- 使用 `getOpenid` 云函数获取当前用户的 OPENID；
- 使用原生小程序页面和自定义 TabBar 组织社区界面；
- 处理用户资料授权、系统选图面板和相册权限；
- 通过本地状态模块实现关注、点赞、收藏、评论和未读消息体验；
- 实现作者照片删除、云端文件清理和本地会话退出。

项目开发环境为微信开发者工具、微信小程序原生框架和微信云开发，项目 AppID 为 `wx725892196e4ed2b2`。

### 4. 云开发初始化与用户身份

`app.js` 在小程序启动时初始化云能力，并在全局状态中保存用户资料、OPENID 以及正在进行的 OPENID 请求：

```javascript
App({
  onLaunch: function () {
    this.globalData = {
      userInfo: null,
      openid: null,
      openidPromise: null,
      loggedOut: false
    }

    wx.cloud.init({ traceUser: true })
  }
})
```

`requestUserProfile()` 使用 `wx.getUserProfile()` 获取展示头像和昵称所需的用户资料；`ensureOpenId()` 调用 `getOpenid` 云函数，并缓存 Promise，避免用户连续操作时重复请求身份信息。上传前会串行完成用户授权和 OPENID 获取，再打开系统选图面板，避免多个原生弹窗同时出现。

项目还提供 `clearSession()`，退出时清空全局用户资料、OPENID 和 OPENID 请求缓存，并设置会话退出标记。由于微信小程序 CloudBase 使用微信原生身份，退出登录表示退出本应用会话，不会注销微信账号本身。

### 5. 云数据库与云存储设计

项目使用名为 `photos` 的云数据库集合。云开发会自动注入 `_id` 和 `_openid`，前端写入的主要字段如下：

| 字段 | 作用 |
| --- | --- |
| `photoUrl` | 云存储图片文件 ID |
| `avatarUrl` | 图片作者头像 |
| `country` / `province` | 图片作者所在地区 |
| `nickName` | 图片作者昵称 |
| `addDate` | 兼容教材要求的日期字符串 |
| `createdAt` | 云端时间，用于可靠排序 |
| `caption` | 用户填写的可选图片文案 |

集合权限设置为“所有用户可读，仅创建者及管理员可写”。用户上传图片时，文件以 `photos/OPENID/时间戳-随机数.扩展名` 的形式保存到云存储，再将返回的 `fileID` 写入数据库。照片作者可以删除自己的照片，删除流程先清理云存储文件，再删除对应的 `photos` 数据记录；数据库权限仍负责从云端校验创建者身份。

数据写入失败时，程序会调用 `wx.cloud.deleteFile()` 删除刚刚上传的文件，避免云存储中留下没有数据库记录的孤立文件。集合中的 `_openid` 由云开发自动维护，不由前端手动写入。

### 6. 社区首页与图片流

首页在 `onShow()` 中加载图片列表，因此从上传页返回时可以及时看到最新发布内容。图片按照 `createdAt` 倒序排列，单次加载 8 条数据，使用 `skip()` 和 `limit()` 实现分页，并通过 `onReachBottom()` 加载更多。

首页还实现了下拉刷新、空状态、加载状态和错误重试。搜索框会根据作者昵称、所在地和图片文案进行本地过滤；“社区”和“关注”两个 feed 标签分别显示全部图片或已关注作者的图片。

```javascript
photos
  .orderBy('createdAt', 'desc')
  .skip(currentList.length)
  .limit(that.data.pageSize)
  .get()
  .then(function (res) {
    var nextList = currentList.concat(res.data)
    that.setData({
      photoList: nextList.map(photoUtils.normalizePhoto),
      hasMore: res.data.length === that.data.pageSize
    })
  })
```

每张图片卡片包含作者头像、昵称、所在地、序号、图片、文案、发布日期以及点赞和收藏操作。点击头像进入个人主页，点击图片进入详情页。

```javascript
var cloudPath = 'photos/' + openid + '/' +
  Date.now() + '-' + Math.floor(Math.random() * 10000) + '.' + extension

wx.cloud.uploadFile({
  cloudPath: cloudPath,
  filePath: filePath,

```

上传按钮具有防重复提交机制，上传过程中会显示进度并暂时禁止再次操作。完成后提示“发布成功”，清空文案输入框并刷新当前用户的历史图片。历史图片按创建时间倒序排列，点击图片可调用 `wx.previewImage()` 进行预览。

### 10. 社区互动状态

`utils/social.js` 对关注、点赞、收藏、评论和消息状态进行统一管理。首页和详情页通过 `decoratePhoto()` 将当前用户的互动状态合并到图片数据中，交互后只刷新当前展示数据，不需要重新请求整个图片列表。

关注状态用于“关注”图片流筛选；点赞和收藏状态用于卡片与详情页的图标和数量反馈；评论数据用于详情页评论区；未读消息数量同步显示在首页和消息入口。

这些互动状态属于本地体验数据，不改变云数据库中图片的核心记录，避免在实验基础功能之外引入不必要的云端写权限。

退出登录时，`social.clearSession()` 会移除本地保存的关注、点赞、收藏、评论、通知和资料状态，防止下一次使用时继续显示上一位用户的本地互动数据。退出后“我的”页面显示重新登录入口；重新完成用户资料授权和 OPENID 获取后，页面恢复作品管理功能。

### 11. 照片删除与会话退出

“我的”页面的每张作品卡片都提供删除按钮，图片详情页仅在当前 OPENID 与照片 `_openid` 一致时显示删除按钮。删除前弹出二次确认，确认后将照片从云存储和数据库中移除，并刷新作品列表；删除过程中按钮进入 loading 状态，避免重复提交。

```javascript
var removeFile = photo.photoUrl
  ? wx.cloud.deleteFile({ fileList: [photo.photoUrl] })
  : Promise.resolve()

Promise.resolve(removeFile).then(function () {
  return photos.doc(photo._id).remove()
})
```

详情页在加载公开照片时不会因为身份判断失败而阻止照片展示，只会隐藏删除入口。这样公开浏览和作者管理彼此独立，同时依赖 `photos` 集合权限保护实际删除操作。

退出登录按钮位于“我的”页面底部。用户确认后，页面清空当前作品和资料，并显示“你已退出登录”；点击“重新登录”后重新请求用户资料和 OPENID。云端照片不会因退出登录而删除。

## 二、问题总结与体会

### 1. 实验中遇到的问题及解决方法

（1）**用户未授权时直接进入上传页会导致资料为空。** 上传记录需要头像、昵称、地区和 OPENID。解决方法是在首页进入上传页之前统一调用 `requestUserProfile()` 和 `ensureOpenId()`，上传页再次校验并补充全局身份信息。

（2）**用户授权弹窗和系统选图面板同时弹出。** 两个原生面板同时调用时可能互相抢占，导致其中一个无法正常显示。解决方法是将授权、获取 OPENID 和选图操作串成 Promise 链，前一步完成后再打开下一步。

（3）**图片上传成功但数据库写入失败会留下无效文件。** 云存储上传和数据库写入是两个独立操作。解决方法是在数据库写入失败的 catch 分支中调用 `wx.cloud.deleteFile()` 清理刚上传的文件。

（4）**仅使用日期字符串排序时，同一天的图片顺序不稳定。** 教材字段 `addDate` 只有年月日，无法区分同一天内的多次上传。解决方法是增加 `createdAt: db.serverDate()`，优先按云端时间排序，并保留 `addDate` 兼容教材要求。

（5）**图片列表一次性加载过多会影响体验。** 直接读取全部图片会增加等待时间和数据量。解决方法是使用 `skip()`、`limit()` 和 `onReachBottom()` 实现分页，同时通过 `hasMore` 避免无数据时重复请求。

（6）**从上传页返回首页后看不到刚发布的图片。** 如果只在首页 `onLoad()` 中请求数据，页面再次显示时不会自动刷新。解决方法是在首页 `onShow()` 中重置并加载图片列表，并支持下拉刷新。

（7）**模拟器无法保存图片到相册。** 模拟器通常没有真实系统相册。解决方法是区分权限错误和模拟器保存失败，真机提示用户授权，模拟器显示“无相册时属正常现象”的说明。

（8）**页面内容可能被自定义 TabBar 或浮动上传按钮遮挡。** 解决方法是在公共 `.container` 中增加底部 padding，并将浮动按钮放置在安全区域上方，保证列表末尾和操作按钮都可见。

（9）**基础实验页面与完整社区体验之间存在差距。** 教材只要求基础图片列表和详情操作，项目进一步加入了关注、点赞、收藏、评论和消息页面。解决方法是把这些交互放入 `social.js` 统一管理，使云数据库核心流程仍然保持简单，扩展功能也不会散落在各个页面中。

（10）**删除照片需要同时处理云存储和数据库。** 如果只删除数据库记录，云存储中会留下无法访问的文件；如果只删除云文件，社区中仍可能出现失效图片。解决方法是删除前进行作者身份判断和二次确认，按顺序删除云文件与数据库记录，并在操作过程中锁定按钮防止重复提交。

（11）**微信小程序没有传统 Web 式注销接口。** CloudBase 小程序身份由微信自动提供，不能照搬 Web 登录/注销流程。解决方法是将“退出登录”实现为本地应用会话退出：清理全局身份缓存、移除 `social.js` 本地状态、清空页面数据，并提供重新授权和重新获取 OPENID 的入口；云端照片保留不变。

### 2. 实验收获与体会

通过本次实验，我完成了一个基于微信云开发的图片分享社区，理解了小程序前端页面、云数据库、云存储和云函数之间的协作关系。图片文件适合保存在云存储，图片作者和日期等元信息适合保存在云数据库，而用户身份则通过云函数从微信运行环境中安全获取。

本次实验让我认识到，云开发项目的难点不仅是把功能“接通”，还包括异步流程、权限、错误反馈和数据一致性。授权、身份获取、选图、上传和数据库写入必须按照正确顺序执行；上传成功但写库失败时还要及时清理云文件；分页和下拉刷新则需要考虑重复请求和列表状态合并。

在交互设计方面，空状态、上传进度、错误重试、相册权限说明和模拟器差异都会影响用户是否能够顺利完成任务。将这些边界情况提前纳入页面设计后，应用的可用性和稳定性都有所提高。

在工程结构方面，将图片规范化、错误转换、社区互动状态和会话清理抽离到公共模块，使页面代码更加清晰，也便于后续增加新的互动功能。通过本次实验，我进一步熟悉了从云能力初始化、数据模型设计、文件与记录一致性、页面开发到真机验收的完整小程序开发流程。
