# 架构与专业术语

## 1. 架构是什么

“架构”可以理解为项目的组织方式：数据放在哪里、页面怎样取得数据、用户点击后去哪里、不同功能之间如何避免互相冲突。

当前项目采用最简单的三层结构：

```text
本地数据层 data/
        ↓
查询工具层 utils/
        ↓
页面展示层 pages/
```

这不是后端服务，也不需要云数据库。

## 2. 数据模型

“数据模型”是对现实信息的结构化描述。例如一个地点不是一整段散文，而是由若干明确字段组成：

```js
{
  id: 'mohe',
  name: '漠河',
  latitude: 52.9723,
  longitude: 122.5386,
  summary: '长途北上后抵达的极北小城。'
}
```

这样地图、行程和详情页都可以读取同一个“漠河”，不会在三个页面分别写三份内容。

当前核心模型包括：

- `Place`：地点；
- `Segment`：两个地点之间的一段交通；
- `TripDay`：某一天的行程；
- `Guide`：一篇主题攻略；
- `BudgetPlan`：预算计算使用的路线方案。

## 3. 唯一数据源

“唯一数据源”表示同一条业务信息只维护一次。当前文件是：

```text
mysummerapp/data/trip-data.js
```

例如“哈尔滨 → 漠河”的费用以后只应在对应路段对象中修改。行程页和路段详情页会一起得到新值，避免一个页面写 ¥100、另一个页面写 ¥120。

## 4. ID 与关联

`id` 是对象的唯一代号。页面跳转时不把整个对象塞进网址，只传一个 id：

```text
/pages/place-detail/place-detail?id=mohe
```

详情页收到 `mohe` 后，通过 `utils/data-query.js` 找到漠河对象。这种做法称为“通过 ID 关联”。

## 5. 页面路由

“路由”表示页面路径和页面之间的跳转关系。

- `wx.navigateTo`：进入详情页，会在页面栈中保留上一页，因此可以返回；
- `wx.switchTab`：切换到底部导航页面，例如从预算攻略进入工具页；
- `wx.navigateBack`：返回上一页，当前项目的自定义导航栏已经封装了这个行为。

“页面栈”可以想象成叠在一起的一摞页面：进入详情时放上一张，返回时拿掉最上面一张。

## 6. 页面状态

“状态”是页面当前所处的情况，例如：

- 正常态：数据完整，显示正常内容；
- 空态：没有照片或评分，显示说明；
- 异常态：地图加载失败，提供重新加载和地点列表；
- 选中态：预算选项被选中，使用不同样式；
- 展开态：某一天的时间轴内容已经展开。

代码中的 `this.setData()` 用于修改页面状态，并让界面同步更新。

## 7. 本地存储

“本地存储”是把少量数据保存在用户手机内，例如 P1 的收藏和行李清单。常用接口是 `wx.setStorageSync` 和 `wx.getStorageSync`。

P0 目前不需要保存用户输入。预算选项在当次页面使用中有效，重新进入时恢复推荐默认值。后续实现 P1 时再接入本地存储。

## 8. 云开发

“云开发”提供云数据库、云函数和云存储，适合登录、跨设备同步、用户上传等功能。P0 的内容是只读旅行资料和本地计算，因此暂时不开通云服务，能减少配置和故障点。
