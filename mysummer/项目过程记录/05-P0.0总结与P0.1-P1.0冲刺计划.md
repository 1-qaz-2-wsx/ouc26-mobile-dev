- 路段：12 个；真实距离、时长和实付费用均待补。

- 攻略：5 篇基础短文，仍需真实经历扩充。

### 3. 当前主要问题

1. **数据真实性不足**：功能能运行，但尚不能作为真实旅行记录展示。
2. **地图调试受限**：项目启用 Skyline，Windows 开发者工具暂不显示地图；真机可测试，但降低开发效率。
3. **里程口径未确定**：经纬度直线距离、铁路运营里程和实际道路里程不能混为一谈。
4. **界面仍是结构稿**：色彩和卡片体系已有方向，但没有真实照片，无法完成最终视觉节奏。
5. **P1 尚未实现**：官方资源、行李清单、路线方案、收藏、图片预览仍待开发。

## 三、里程自动计算方案

### 1. 不能直接使用地图折线长度

当前地图折线只是连接城市坐标。两点经纬度只能计算直线距离，不等于：

- 火车实际运营里程；
- 公路客运行驶里程；
- 轮渡航线距离；
- 混合交通的真实总里程。

### 2. 数据字段约定

后续每个路段增加：

```text
distanceKm       页面展示的实际/参考里程
distanceSource   manual | official | map_api | estimated
distanceNote     来源说明
```

### 3. 实现顺序

- 火车、轮渡：优先录入票据、运营方或可靠记录中的里程；地图 API 不适合还原铁路和航线。
- 公路客运：可评估腾讯位置服务路线规划 API 自动计算，需要申请 Key、配置服务器域名并选择驾车路线口径。
- 无可靠来源：继续显示“待确认”，不使用城市直线距离冒充实际里程。
- 总里程只汇总来源明确的路段；存在缺失时显示“已确认 X km + 待确认路段”。

“API”是程序调用外部服务的接口。自动地图里程需要联网请求腾讯地图服务，不是 `<map>` 组件自身提供的能力。

## 五、优先级与延期规则

### 必须保证

1. 真实路线和数据一致；
2. 地图、行程、详情和预算可用；
3. P1 五项核心功能闭环；
4. 真机可正常演示；
5. 图片与票据不泄露隐私。

### 时间不足时可以缩减

- 减少攻略篇数，但保留结构完整的代表攻略；
- 减少每个地点的照片数量；
- UI 动效降级为静态过渡；
- 地图 API 自动里程降级为有来源的手工里程。

### 不允许通过以下方式赶工

- 编造日期、费用、班次或距离；
- 把未知金额当成 0；
- 添加不可点击的假入口；
- 未脱敏直接展示票据；
- 为追求视觉效果牺牲信息可读性。

## 六、每日验收节奏

每天上午确定当天唯一主目标；晚上按以下问题复盘：

1. 今天实际完成了哪些可验证结果？
2. 哪些数据仍缺失，是否明确标记？
3. 是否产生地图、预算或页面间数据不一致？
4. 真机是否验证？如果没有，原因是什么？
5. 明天最先解决的阻塞是什么？
