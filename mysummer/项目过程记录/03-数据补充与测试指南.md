# 数据补充与测试指南

## 1. 需要补充的真实资料

当前 P0 功能已经可以运行，但以下内容必须根据你本人的旅行资料补齐：

- 每天的真实日期；
- 每个路段的距离、出发/到达时间、时长和实付交通费；
- 每个地点的住宿、餐饮、当地交通、门票和其他费用；
- 实拍照片与文字游记；
- 预算方案中的真实参考费用；
- 更准确的地点坐标；
- 评分与踩坑说明。

主要修改文件：

```text
mysummerapp/data/trip-data.js
```

## 2. 为什么未知值使用 null

示例：

```js
actualCost: null
```

`null` 表示“目前不知道”，页面会显示“待补”。不要为了让页面看起来完整而填写 0，因为 0 的含义是“确实免费”。

真实补齐后可以改成：

```js
actualCost: 152.5
```

金额只写数字，人民币符号由页面统一添加。

## 3. 如何补充图片

建议在 `mysummerapp/assets/images/` 下按类型整理：

```text
assets/images/places/
assets/images/segments/
assets/images/guides/
```

P0 初期可以使用本地压缩图。若代码包接近微信限制，再把大图迁移到合法的网络资源或云存储。不要一开始就上传未经筛选的全部原图。

补图时需要同时修改数据对象中的图片路径，并把页面当前的“照片待补”占位区域替换为 `image` 或图片列表组件。

## 4. 微信开发者工具检查步骤

### 第一次编译

1. 打开微信开发者工具；
2. 导入 `mysummerapp` 目录；
3. 确认 AppID 为项目原有的 AppID；
4. 点击“编译”；
5. 检查底部是否出现“地图、行程、攻略、工具”四项。

### 页面检查

- 地图：能看到路线和地点 Marker；点击 Marker 后出现地点卡；
- 行程：能展开 Day，并分别进入地点和路段；
- 攻略：每张攻略卡可以进入详情；预算攻略能跳转工具页；
- 工具：任意切换路线、住宿、饮食，数字立即变化；重置恢复 7 天 + 青旅 + ¥70/天；
- 返回：详情页左上角返回能回到原页面。

### 异常检查

- 临时关闭网络，检查文字与本地数据是否仍可显示；
- 地图加载失败时，应出现地点列表和“重新加载地图”；
- 打开没有评分的地点，应显示“评分尚未整理”，不能显示 0 分；
- 打开费用未知的地点或路段，应显示“待补”，不能显示 ¥0。

## 5. 预算人工验算

当前 7 天推荐方案：

```text
交通：870
住宿：70 × 6 = 420
饮食：70 × 7 = 490
门票：190
其他：0
基础总额：870 + 420 + 490 + 190 = 1970
应急预算：1970 × 15% = 295.5，四舍五入为 296
建议携带总额：1970 + 296 = 2266
```

工具页显示的数字应与上述结果一致。

## 6. 每次改数据后的检查

1. 检查 JavaScript 的逗号、引号和括号是否完整；
2. 编译并观察控制台是否有红色错误；
3. 从地图和行程分别进入同一地点，确认内容一致；
4. 从行程和地点详情进入同一路段，确认费用和时间一致；
5. 修改预算数据后，重新做一次人工验算；
6. 真机预览，检查长标题、地图和滚动是否正常。
