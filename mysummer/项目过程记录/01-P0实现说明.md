# P0 实现说明

## 1. 工程现状

微信开发者工具创建的初始工程位于 `mysummerapp/`。该目录已经带有真实 AppID，因此本次保留原有 `project.config.json` 和自定义导航栏组件，在原框架中继续开发，没有另建重复项目。

源代码直接位于 `mysummerapp/`，这是开发者工具当前生成的结构。PRD 和过程文档位于其外部，因此不会被打进小程序代码包。

## 2. 页面结构

### 四个 Tab 页面

“Tab 页面”指底部导航可以直接切换的一级页面。

| 页面 | 路径 | 主要功能 |
| --- | --- | --- |
| 地图 | `pages/index/index` | 路线地图、地点 Marker、地点摘要和降级列表 |
| 行程 | `pages/itinerary/itinerary` | 18 天纵向时间轴、地点和路段入口 |
| 攻略 | `pages/guides/guides` | 按固定顺序展示主题攻略 |
| 工具 | `pages/tools/tools` | 三类路线、三档住宿、三档饮食的预算计算 |

### 三个详情页面

“共享详情页”表示它可以从多个入口进入，但始终读取同一份数据。

| 页面 | 路径 | 可能的入口 |
| --- | --- | --- |
| 地点详情 | `pages/place-detail/place-detail` | 地图、行程、攻略 |
| 路段详情 | `pages/segment-detail/segment-detail` | 行程、地点、攻略 |
| 攻略详情 | `pages/guide-detail/guide-detail` | 攻略首页 |

## 3. 已实现的关键规则

### 地图

- 按真实路线顺序绘制折线；
- 每个城市只有一个 Marker；
- 哈尔滨、烟台等重复经过的地点在一个 Marker 上标出到访次数；
- 点击 Marker 后显示摘要卡，再进入地点详情；
- 地图加载失败时仍显示地点列表，用户不会被困在空页面。

### 行程

- Day 1 到 Day 18 连续存在；
- 有移动记录的日期默认展开；
- 地点卡和路段卡使用不同入口；
- 跨夜交通明确显示“跨夜 · 次日到达”；
- 缺少日期时显示“日期待补”。

### 详情页

- 地点详情区分照片、旅行记录、实际费用、评分、建议和相邻路段；
- 路段详情区分基础摘要、时间线、沿途记录、踩坑和起终点；
- 攻略详情提供目录、正文、关联地点/路段和预算入口；
- 无照片、费用、评分、时间线时都有可理解的占位状态。

### 预算计算器

计算公式：

```text
住宿费 = 每晚单价 × 住宿晚数
饮食费 = 每日饮食标准 × 旅行天数
基础总额 = 交通 + 住宿 + 饮食 + 门票 + 其他
应急预算 = 基础总额 × 15%（四舍五入）
建议携带总额 = 基础总额 + 应急预算
```

目前三套路线中的价格是“原型参考值”，用于确认计算器能够工作，不宣称是实际旅行花费或实时票价。补齐真实资料后必须替换。

## 4. 注释策略

代码注释重点放在“为什么这样做”，例如：

- 为什么未知金额不能按 0 计算；
- 为什么重复城市只创建一个 Marker；
- 为什么页面只保存 id，再到统一数据源中查询；
- 为什么应急预算不直接混进基础总额。

简单的样式声明和一眼能看懂的点击跳转没有逐行注释，避免注释比代码更难读。
