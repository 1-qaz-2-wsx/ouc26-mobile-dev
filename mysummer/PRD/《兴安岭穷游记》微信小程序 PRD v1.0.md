# 《兴安岭穷游记》微信小程序 PRD v1.0

## 一、产品基本信息

**产品名称：** 兴安岭穷游记
**产品类型：** 微信小程序
**项目性质：** 《移动软件开发》课程大项目
**课程主题：** 我的暑假生活
**版本：** PRD v1.0 Frozen
**核心关键词：** 兴安岭、东北旅行、穷游、路线可视化、真实经验、信息整合

------

# 二、项目背景

本项目基于一次真实暑假旅行：

> 青岛 → 烟台 → 大连 → 长春 → 南岔 → 汤旺河 → 哈尔滨 → 漠河 → 满归 → 海拉尔 → 哈尔滨 → 烟台 → 青岛

旅行以低预算、公共交通、长距离移动为主要特点，途经海滨城市、东北城市、小兴安岭、大兴安岭以及呼伦贝尔地区。

传统旅游平台往往围绕“目的地”组织内容，例如“哈尔滨攻略”“漠河攻略”，而本项目希望围绕一条**真实发生过的旅行路线**进行组织。

产品不仅展示“我去了哪里”，更关注：

- 我是如何从 A 到 B 的；
- 实际花费和时间是多少；
- 路上是什么体验；
- 哪些地方值得停留；
- 哪些环节容易踩坑；
- 其他旅行者如果想复刻，需要知道什么；
- 去哪里确认最新的交通、预约和景区信息。

因此，本项目并非单纯的电子游记，而是一款：

> **真实旅行路线展示 + 可复刻穷游攻略 + 官方出行信息整合**

的微信小程序。

------

# 三、产品定位

## 3.1 一句话定位

> **以一条真实的兴安岭穷游路线为核心，通过地图、时间轴、实地经验、交通费用和官方信息入口，为用户提供可浏览、可参考、可复刻的旅行体验。**

------

## 3.2 产品核心价值

产品解决四个问题。

### 1. 我去了哪里？

通过地图和完整路线展示旅行的空间轨迹。

### 2. 我是怎么走的？

通过时间轴和路段详情展示地点之间的移动过程。

### 3. 如果你也想去，应该怎么准备？

通过地点攻略、交通、预算、踩坑建议提供实际参考。

### 4. 真正出发前应该去哪里确认信息？

通过官方公众号、景区入口、预约渠道、公交信息等内容降低信息搜集成本。

------

# 四、产品差异化

本产品不与携程、马蜂窝、小红书等大型旅游产品竞争全面旅游信息，而聚焦于一条具体、真实、具有个人特色的东北及兴安岭穷游路线。

核心差异包括：

### 4.1 从“目的地中心”转向“路线中心”

传统方式：

> 漠河有什么景点？

本产品：

> 哈尔滨怎么到漠河？
> 漠河怎么到满归？
> 这段路多久？
> 花多少钱？
> 有没有必要这么走？

------

### 4.2 从“网络攻略”转向“真实验证”

优先展示：

> 我实际坐过什么车、花了多少钱、住了哪里、遇到了什么问题。

而不是大量转载第三方攻略。

------

### 4.3 从“信息展示”进一步延伸到“信息入口”

对于具有时效性的内容，例如：

- 公交班次；
- 景区预约；
- 门票政策；
- 开放时间；
- 临时闭园；
- 轮渡情况；

小程序不尝试承担全部实时更新责任，而是帮助用户快速找到正确的官方信息源。

------

# 五、目标用户

## 5.1 核心用户

希望前往东北、兴安岭、漠河、呼伦贝尔旅行的年轻旅行者。

主要特征：

- 大学生或年轻游客；
- 预算有限；
- 偏向自由行；
- 不以自驾为主要方式；
- 依靠火车、轮渡、公交等公共交通；
- 喜欢森林、草原、铁路、小城等自然与人文景观；
- 愿意接受较长时间的跨城市移动。

------

## 5.2 次级用户

对以下内容感兴趣的普通浏览者：

- 兴安岭自然风光；
- 东北铁路旅行；
- 青年穷游；
- 暑假旅行记录；
- 长距离公共交通旅行。

------

# 六、产品设计原则

## 6.1 路线优先

地点不是孤立的信息页面，而是整条旅途中的一个节点。

------

## 6.2 真实经验优先

第一信息源是本人真实旅行经历。

------

## 6.3 实用信息与旅行叙事并存

页面既包含照片、文字和情绪，也包含：

- 时间；
- 费用；
- 交通；
- 住宿；
- 注意事项。

------

## 6.4 官方信息优先于第三方攻略聚合

第三方个人攻略不作为核心产品能力。

优先整合：

- 官方公众号；
- 官方小程序；
- 景区官网；
- 官方预约入口；
- 公共交通信息；
- 官方联系电话。

------

## 6.5 信息时效必须明确

动态信息必须标注更新时间，并提醒用户出发前再次确认。

------

## 6.6 少而完整

优先保证核心用户路径完整，而不是堆积大量半成品功能。

------

# 十三、第三方信息使用原则

关于外部信息，正式冻结以下原则。

## 13.1 不以个人攻略聚合为主要功能

小红书、马蜂窝、个人博客等内容原则上不作为核心外链。

------

## 13.2 优先官方渠道

优先级：

> 官方小程序
> → 官方公众号
> → 官方网站
> → 官方电话
> → 权威公共服务渠道

------

## 13.3 每个入口必须注明用途

不能仅显示：

> 漠河文旅

而应该显示：

> **漠河文旅**
> 用于查询当地旅游公告、景区动态与活动信息。

------

## 13.4 区分“我的经历”和“当前信息”

例如：

> 我在 2026 年暑假实际乘坐 XX 班次。

属于：

**历史旅行记录**

而：

> 当前班次是否仍然运行？

属于：

**动态信息**

必须引导用户向官方重新确认。

# 十六、MVP 验收标准

项目达到以下状态，即可视为 MVP 完成。

## 首次体验

用户打开小程序后 **5 秒内**理解：

> 这是一次兴安岭长距离穷游。

------

## 路线理解

用户在 **10 秒内**能够看到：

- 从哪里出发；
- 去过哪些地方；
- 整体路线如何。

------

## 内容获取

用户在 **30 秒内**能够：

- 点击任意主要地点；
- 查看照片；
- 查看旅行记录；
- 查看费用和建议。

------

## 路段理解

用户可以明确看到：

> A → B 怎么走、多久、多少钱。

------

## 实用功能

用户可以正常使用预算计算器并得到计算结果。

------

## 系统完整性

必须保证：

- 所有主要按钮可点击；
- 页面之间正常跳转；
- 可以正常返回；
- 图片正常加载；
- 地图正常显示；
- 数据正常读取；
- 无大量空页面；
- 不存在明显无响应假按钮。

# 十九、最终产品定义

以后课程报告、答辩、README 都可以基于这段修改：

> **《兴安岭穷游记》是一款基于真实暑假旅行经历开发的微信小程序。产品以青岛出发、途经东北城市并穿越大小兴安岭的真实旅行路线为核心，通过地图可视化和时间轴展示完整旅程，并记录各地点及路段的真实照片、交通方式、时间成本、旅行费用与个人体验。同时，产品通过穷游攻略、预算计算工具以及官方交通、景区预约和公共服务信息入口，为希望复刻类似路线的用户提供实际参考，降低偏远地区自由行过程中存在的信息搜集成本。**

**PRD v1.0 至此冻结。**

后续除非发现**影响核心用户路径的硬性问题**，否则不再增加一级模块，也不再改变“地图 / 行程 / 攻略 / 工具”四 Tab 架构。接下来应该直接进入**低保真原型与页面交互设计**，而不是继续扩需求。
