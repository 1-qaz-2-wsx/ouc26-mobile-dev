## 一、版本说明

### 1.1 本次修订目标

PRD v1.1 不改变 v1.0 已冻结的产品定位、四 Tab 架构和七类页面，只将页面与主要功能细化到可直接绘制低保真原型、拆分开发任务和进行验收的程度。

本次重点补充：

- 页面内容顺序、组件、交互、跳转和返回规则；
- 加载态、空态、异常态与内容降级方式；
- 地图、时间轴、预算计算器和官方资源的具体规则；
- 页面共用的数据源、字段口径和内容可信度规范；
- P0/P1 功能矩阵及页面级验收用例。

### 1.2 版本边界

- 保留“地图 / 行程 / 攻略 / 工具”四个一级 Tab；
- 保留地图首页、行程页、地点详情、路段详情、攻略首页、攻略详情、工具页七类页面；
- P0 构成首版 MVP；P1 写清入口与规则，但不并入 MVP；
- 不增加登录、后台管理、交易、社区、实时交通或实时票价；
- 缺少的真实日期、金额、照片、坐标和官方渠道统一标记为 `【待补】`，不得编造。

## 二、产品概述

### 2.1 产品定位

《兴安岭穷游记》是一款基于真实暑假旅行经历开发的微信小程序，以一条从青岛出发、途经东北城市并穿越大小兴安岭的长距离公共交通路线为核心，通过地图、时间轴、地点与路段记录、主题攻略和预算工具，帮助用户看懂、评估并准备复刻这趟旅行。

真实路线：

> 青岛 → 烟台 → 大连 → 长春 → 南岔 → 汤旺河 → 哈尔滨 → 漠河 → 满归 → 海拉尔 → 哈尔滨 → 烟台 → 青岛

### 2.2 核心价值

| 用户问题 | 产品回答方式 |
| --- | --- |
| 我去了哪里？ | 地图展示完整空间轨迹与主要停靠点 |
| 我是怎么走的？ | 时间轴与路段详情展示移动顺序、交通、时间和花费 |
| 如果想复刻，需要知道什么？ | 地点建议、主题攻略、预算与踩坑记录 |
| 出发前去哪里确认最新信息？ | P1 官方渠道、预约入口、电话与更新时间 |

### 2.3 目标用户

核心用户为计划前往东北、兴安岭、漠河或呼伦贝尔的大学生和年轻自由行游客。他们预算有限，以火车、轮渡、客运和公交为主要交通方式，愿意接受长距离移动，希望获得经过真实旅行验证的信息。

次级用户为对东北铁路旅行、森林草原、青年穷游或暑假旅行记录感兴趣的普通浏览者。

### 2.4 设计原则

1. **路线优先：** 地点必须处于完整旅程上下文中。
2. **真实优先：** 清楚区分本人历史经历与当前动态信息。
3. **实用与叙事并存：** 每页既能看旅行，也能查时间、费用与建议。
4. **官方优先：** 动态信息优先指向官方渠道，不聚合大量第三方攻略。
5. **时效明确：** 动态信息必须展示核验日期并提示再次确认。
6. **少而完整：** P0 先保证核心路径完整，不堆积半成品入口。

## 三、信息架构与页面流转

### 3.1 一级导航

底部导航固定为四个 Tab：

| Tab | 图标语义 | 核心问题 | 默认页面 |
| --- | --- | --- | --- |
| 地图 | 地图/路线 | 我去了哪里？ | 地图首页 |
| 行程 | 火车/时间轴 | 我是怎么走完这趟旅行的？ | 行程页 |
| 攻略 | 背包/手册 | 复刻路线需要知道什么？ | 攻略首页 |
| 工具 | 计算器/清单 | 需要多少钱、做什么准备？ | 工具页 |

### 3.2 页面清单

| 编号 | 页面 | 层级 | 主要入口 | 返回规则 |
| --- | --- | --- | --- | --- |
| P01 | 地图首页 | Tab | 默认启动、点击地图 Tab | 再次点击 Tab 回到默认地图视野 |
| P02 | 行程页 | Tab | 点击行程 Tab | 保留本次浏览位置；再次点击 Tab 回到时间轴顶部 |
| P03 | 地点详情 | 二级共享页 | 地图 Marker、行程地点节点、攻略关联地点 | 返回原入口页及原滚动/地图状态 |
| P04 | 路段详情 | 二级共享页 | 行程路段节点、地点相邻路段、攻略关联路段 | 返回原入口页及原滚动状态 |
| P05 | 攻略首页 | Tab | 点击攻略 Tab | 保留本次滚动位置；再次点击 Tab 回到顶部 |
| P06 | 攻略详情 | 二级页 | 攻略卡片 | 返回攻略首页原位置 |
| P07 | 工具页 | Tab | 点击工具 Tab、攻略中的预算入口 | 跨 Tab 进入时定位到对应工具分区 |

### 3.3 页面流转图

```text
启动小程序
   │
   ▼
[地图首页] ──点击 Marker/卡片──> [地点详情]
   │                                  │
   │                                  ├──上一段/下一段──> [路段详情]
   │                                  └──P1 官方资源操作
   │
底部 Tab
   ├──> [行程页] ──地点节点────────> [地点详情]
   │              └─路段节点────────> [路段详情]
   │
   ├──> [攻略首页] ──攻略卡片──────> [攻略详情]
   │                                  ├──关联地点──> [地点详情]
   │                                  ├──关联路段──> [路段详情]
   │                                  └──算预算────> [工具页/预算区]
   │
   └──> [工具页]
          ├──P0 预算计算器
          ├──P1 行李清单
          └──P1 路线方案
```

### 3.4 导航约束

- Tab 页面之间使用 `switchTab` 语义；二级详情页使用普通页面栈。
- 详情页不得自行改变底部 Tab 选中状态。
- 从攻略详情跳转工具页属于跨 Tab 跳转，工具页需自动滚动到预算区并保留攻略页返回路径不作为强制要求；用户通过攻略 Tab 可再次找到原攻略。
- 同一地点或路段无论从哪里进入，都读取相同对象；入口只影响返回位置，不影响内容。
- P0 不出现点击后无结果的占位按钮。未实现的 P1 入口在开发版中标注“P1”，正式 MVP 可隐藏。

## 四、全局交互与状态规范

### 4.1 页面骨架

手机竖屏下，页面自上而下由以下区域组成：

1. 微信导航栏或自定义标题区；
2. 页面主内容区；
3. 必要的底部安全区；
4. Tab 页面展示固定底部导航，二级页面不重复展示 Tab。

首屏应优先展示页面核心信息，不用大面积装饰遮挡地图、路线或关键数据。

### 4.2 通用状态

| 状态 | 表现 | 操作 |
| --- | --- | --- |
| 初始加载 | 使用与页面结构一致的骨架屏，避免只显示空白 | 加载完成后原位替换 |
| 局部加载 | 卡片或图片区域显示轻量占位 | 不阻塞页面其他已加载内容 |
| 空态 | 说明缺少什么，如“该地点暂未补充照片” | 有合理去向时提供一个明确操作 |
| 异常态 | 简述失败原因，不展示技术报错 | 提供“重新加载”；仍失败时保留可用文本内容 |
| 离线/网络差 | 本地静态数据继续展示；网络图片和外链单独提示 | 允许重试，不清空已显示内容 |

### 4.3 图片规则

- 首图加载失败时显示森林/铁路主题占位图和地点名称；
- 图片列表为空时隐藏画廊组件，显示一句空态，不保留大块空白；
- P1 图片全屏预览使用微信图片预览能力，支持左右切换和退出；
- 图片必须有地点、路段或攻略归属，不混用无法确认来源的网络图片。

### 4.4 反馈与防误触

- 可点击卡片需有统一的点击反馈和右箭头或按钮文案；
- 复制成功、收藏成功、重置成功使用轻提示；
- 外链打开失败、本地存储失败使用明确提示，并保留重试路径；
- 预算选项变化后即时更新结果，不额外设置“提交”按钮；
- “重置预算”和“清空清单”属于会丢失本地状态的操作：重置预算直接执行并提示，清空已勾选清单需二次确认。

### 4.5 可读性与可用性

- 正文、金额和按钮不能仅靠颜色区分状态；
- 点击热区不小于微信小程序常用可触控尺寸；
- 长标题最多两行，超出省略；关键地点名和金额不得被截断；
- 星级评分同时显示数字，如“4.5 / 5”，避免只显示图标；
- 动态信息的核验日期和风险提示在正文中可直接看到，不藏在弹窗内。

## 五、页面详细规格

## 5.1 地图首页（P01）

### 页面目标

用户首次打开后 5 秒内识别这是一次兴安岭长距离穷游，10 秒内看懂起点、主要停靠地和整体走向。

### 进入与退出

- 默认启动页；点击底部“地图”进入。
- 点击地点 Marker 后留在本页并打开地点摘要卡；点击卡片进入地点详情。
- 从地点详情返回时，恢复原地图缩放、中心点和已选 Marker。

### 内容与组件顺序

1. **旅行主题条：** 标题“我的兴安岭之旅”、一句副标题、主题照片或渐变背景。
2. **旅行数据总览：** 总天数、停靠节点数、总里程、历史实付总花费；缺少值显示“待补”，不显示假数字。
3. **路线图例：** 起点、普通停靠点、重复停靠点、终点；不同交通方式可使用线型或简短标签，P0 不要求多色复杂图层。
4. **主地图：** Marker、Polyline、地点名称和缩放控件。
5. **地点摘要卡：** 选中 Marker 后从地图底部浮出，不遮挡底部 Tab。

### 地图规则

- 默认视野使用所有有效坐标计算 `include-points`，为上下左右保留安全边距。
- Polyline 严格按 `Segment.displayOrder` 连接，不用地点数组顺序猜测路线。
- 哈尔滨等重复经过的城市使用同一地理 Marker，并显示“经过 2 次”等徽标；点击后摘要卡按经过顺序列出对应 Day，可切换查看，不在同一坐标堆叠多个 Marker。
- 坐标过近导致标签重叠时，优先只显示 Marker；用户放大或点击后再显示名称。P0 不开发复杂聚合算法。
- 某地点无有效坐标时，不绘制 Marker 和关联线段，并在数据审查中报为待补；其他路线仍正常展示。
- 本产品不需要用户实时定位。微信定位权限被拒绝不影响核心地图；如提供“回到完整路线”按钮，该按钮只恢复路线视野，不请求定位。

### 地点摘要卡

展示：经过 Day、地点名、到达来源、主要交通方式、时长、历史实付交通费、最多三个标签和“查看这一站”。重复到访地点允许在卡片内切换不同到访记录。

- 点击 Marker：打开或切换摘要卡；
- 点击地图空白：关闭摘要卡；
- 下滑卡片或点击关闭按钮：关闭卡片；
- 点击“查看这一站”：进入地点详情；
- 仅卡片按钮和明确的可点击区域触发跳转，避免滑动地图时误入详情。

### 状态处理

- 地图组件加载失败：展示简化的纵向地点列表和“重新加载地图”，路线内容仍可浏览。
- Polyline 数据不完整：绘制可用路段，并提示“部分路线信息待补充”。
- 无地点数据：展示产品主题、空态说明和“内容整理中”，隐藏无意义的数据总览。
- 图片加载失败：主题区使用默认森林/铁路占位背景。

### 页面验收

- 首屏可见产品标题、至少两项旅行总览与路线地图主体；
- 默认视野包含全部有效节点；
- 哈尔滨重复到访不会形成无法点击的重叠 Marker；
- 任一有效 Marker 可打开正确卡片并进入对应地点详情；
- 地图失败时仍能通过简化地点列表进入详情。

## 5.2 行程页（P02）

### 页面目标

按真实发生顺序解释每天去了哪里、如何移动，以及哪段行程跨日或需要换乘。

### 时间定义

- `Day 1` 为旅行正式出发的自然日，之后按自然日连续编号；
- 日期使用 `YYYY-MM-DD`，页面可显示为“8 月 1 日 周六”；
- 夜间出发、次日到达的交通归入出发日，并标注“跨夜 · 次日到达”；次日节点仍出现在次日行程中；
- 同一天经过多个地点时，按照实际到达时间排序；无法确定时间时按数据中的 `displayOrder` 排序并显示“时间待补”。

### 进入与退出

- 点击底部“行程”进入。
- 点击地点节点进入地点详情；点击连接两个地点的路段卡进入路段详情。
- 返回时恢复时间轴滚动位置和已展开 Day。

### 内容与组件顺序

1. 页面标题与一句说明；
2. 行程摘要：起止日期、总天数、总路段数；
3. 纵向 Day 时间轴；
4. 每个 Day 内依次展示地点节点、路段节点和简短记录。

### 节点与交互

**Day 头部：** Day、日期、当日标题、当日一句摘要。默认展开首日，其余 Day 保持上次浏览状态；首次进入可全部展开，若内容过长则仅首日展开并由产品实现时统一采用一种方案。

**地点节点：** 封面缩略图、地点名、到达时间、停留信息和一句印象。整张卡片为点击热区。

**路段节点：** `A → B`、交通图标、出发/到达时间、时长、历史实付费用、跨夜或换乘标记。整张卡片为点击热区，不能只让小箭头可点。

**多地点日：** 地点节点和路段节点交替排列，保持真实顺序，不把所有地点和所有交通分成两组。

### 状态处理

- 日期缺失：显示 Day，日期位置显示“日期待补”；
- 封面缺失：使用地点名占位卡，不删除节点；
- 路段费用缺失：显示“费用待补”，不得显示 ¥0；
- 单日无详细记录：仍展示地点与路段，正文显示“旅行记录整理中”；
- 全部行程为空：展示空态，不生成只有线条的时间轴。

### 页面验收

- Day 编号连续，跨夜路段同时可看出出发日和次日到达；
- 同日多个地点顺序正确；
- 地点卡与路段卡点击目标不同且均可返回原位置；
- 行程数据与地图路线顺序一致。

## 5.3 地点详情（P03）

### 页面目标

同时回答“这里是什么体验”“我实际花了多少”“如果你来要注意什么”。

### 进入与退出

- 从地图、行程或攻略关联地点进入；
- 使用系统返回回到原入口和原状态；
- 可通过相邻路段卡进入路段详情。

### 内容与组件顺序

1. **地点 Header：** 地点名、Day/到访日期、地区标签、封面大图；重复到访时显示多个到访日期。
2. **一句话印象：** 最多两行，表达地点在整段旅程中的意义。
3. **旅程位置：** 上一段、本站、下一段；首站或末站只显示存在的一侧。
4. **我的旅行：** 实拍照片、旅行记录与个人体验，标注“旅行记录于【待补日期】”。
5. **实际费用：** 住宿、餐饮、当地交通、门票、其他及总计。
6. **穷游评价：** 预算友好、公共交通、自然景观、独行友好、推荐程度。
7. **如果你也想来：** 推荐停留、交通方式、住宿/吃饭便利、最值得体验、真实踩坑、行李建议。
8. **P1 行前确认：** 官方资源卡片、核验时间和统一风险提示。
9. **P1 收藏：** Header 收藏按钮或页尾收藏操作，使用本地存储。

### 费用规则

- 所有费用默认代表本人该次到访的历史实付金额，模块标题和说明必须写明“我的实际花费”；
- 分类总计为已知费用项之和。任一必要项未知时，总计显示“已记录 ¥X + 待补项”，不得把未知项当作 0；
- 若该地点未住宿，住宿费可显示“未住宿”，其数值按 0 参与已知总计；“未住宿”和“费用未知”必须区分；
- 重复到访地点按到访记录分别展示费用，地点总计可在数据完整后汇总。

### 评分与建议规则

- 评分范围 1.0—5.0，允许 0.5 步进，同时显示星级和数值；
- 没有评分时隐藏该项；五项均无评分时隐藏整个模块并显示轻量说明；
- 建议采用“标签 + 简短说明”，避免连续大段文字；
- 真实踩坑需描述发生条件和应对方式，不只写“很坑”。

### 状态处理

- 无照片：保留地点 Header 占位图，隐藏画廊；
- 无费用：显示“本次费用尚未整理”，不展示全为 ¥0 的表格；
- 无评分或建议：按模块整体降级，不制造空卡片；
- 地点 ID 无效：显示“地点不存在或已调整”并提供返回；
- P1 无官方资源：显示“暂未核验到可用官方入口，请出发前自行确认”，不展示空按钮。

### 页面验收

- 从地图与行程进入同一地点时，标题、费用、评分和建议一致；
- 上一段/下一段指向正确路段；
- 未住宿、未知费用和真实 ¥0 能被区分；
- 任一缺失模块不会造成大片空白或假数据。

## 5.4 路段详情（P04）

### 页面目标

明确回答“A 到 B 怎么走、多久、多少钱、途中有哪些风险”，体现路线中心的产品差异。

### 进入与退出

- 从行程路段节点、地点相邻路段或攻略关联路段进入；
- 返回原入口；
- 起点、终点卡可分别进入对应地点详情。

### 内容与组件顺序

1. **路线 Header：** `起点 → 终点`、路段序号、日期、交通方式；
2. **基础摘要：** 距离、总时长、历史实付费用、是否换乘、是否跨夜；
3. **我的实际路线：** 按时间排序的出发、换乘、停靠和到达节点；
4. **交通凭证说明：** 车次/船次/班次、购票渠道和凭证照片（敏感信息需遮挡）；
5. **沿途记录：** 车站、火车、道路、森林和途中体验；
6. **踩坑与风险：** 班次、换乘、补给、通信、夜间到达等；
7. **路段评价：** 性价比、风景、折腾程度、推荐程度；
8. **起终点关联卡：** 进入起点和终点详情；
9. **P1 交通官方信息：** 官方渠道、电话、网页或二维码。

### 时间与费用规则

- 总时长优先根据真实出发与到达时间计算；无法精确计算时显示原始记录值并标记“约”；
- 跨日时间线同时显示日期，如“8 月 3 日 20:10 出发 / 8 月 4 日 07:30 到达”；
- 换乘节点需包含地点、到达时间、下一程出发时间和等待时长；
- 路段费用是本次从起点到终点的实际交通总成本；分段票价可展开显示；
- 部分票价未知时显示“已记录 ¥X + 待补项”，不输出错误总计。

### 状态处理

- 无时间线：保留基础摘要，显示“详细时间线待补”；
- 无凭证图片：隐藏图片区，保留文字班次信息；
- 无距离：显示“距离待补”，不影响交通、时长和费用；
- 起终点对象缺失：路段页显示已有名称，但禁用无效地点跳转并记录数据错误；
- 外部交通资源不可用：说明“入口可能已调整”，提供复制渠道名称或电话等替代操作。

### 页面验收

- 路段标题、交通、时间和费用与行程页一致；
- 跨夜和换乘路线不产生时间顺序歧义；
- 起点、终点均可正确跳转；
- 凭证图片不展示身份证号、订单号或完整手机号等敏感内容。

## 5.5 攻略首页（P05）

### 页面目标

以主题而非目的地聚合攻略，让用户快速找到路线、交通、预算、住宿和踩坑内容。

### 进入与退出

- 点击底部“攻略”进入；
- 点击攻略卡进入攻略详情；返回时恢复原滚动位置。

### 首批主题与默认排序

P0 不提供搜索和筛选，按 `Guide.displayOrder` 固定排序：

1. 第一次走兴安岭；
2. 公共交通穿越东北；
3. 我的穷游预算；
4. 住宿；
5. 兴安岭旅行；
6. 踩坑记录；
7. P1 行前确认。

### 攻略卡片

每张卡展示封面、标题、分类、两行摘要、预计阅读时长、更新时间和最多三个关联标签。整张卡可点击。P1 内容尚未上线时正式 MVP 不展示该卡，避免“敬请期待”占据核心列表。

### 状态处理

- 封面缺失：使用统一主题占位图；
- 摘要缺失：显示分类说明，不复用整篇正文首段；
- 无攻略：展示“攻略整理中”，但不影响其他 Tab；
- 单篇内容状态为草稿：正式 MVP 不展示，开发环境可标注“草稿”。

### 页面验收

- 攻略按配置顺序展示，不按更新时间随机变化；
- 每张已发布攻略均可打开且有实际内容；
- P0 不出现不可用的搜索框、筛选标签或空分类。

## 5.6 攻略详情（P06）

### 页面目标

用统一、易扫读的图文结构完整解释一个主题，并把用户引向相关地点、路段或预算工具。

### 内容与组件顺序

1. 标题、分类、摘要、更新时间和封面；
2. 简短目录，点击后滚动到对应章节；
3. 正文章节，支持标题、正文、图片、提示卡和简短列表；
4. 相关地点与路段；
5. 与预算相关的文章展示“去算预算”，跨 Tab 进入工具页预算区；
6. P1 官方资源入口；
7. P1 收藏。

推荐模板：

```text
01 我的实际路线
02 最困难的一段
03 交通方式
04 我的实际花费
05 需要提前准备什么
06 适合什么人
07 官方信息入口（P1）
```

### 内容规则

- 不开发内容编辑器，攻略由结构化本地数据或 Markdown-like 内容配置生成；
- 目录只展示实际存在的章节；
- 引用历史费用时标注旅行日期，不能表现为当前实时价格；
- 关联对象必须使用有效 ID，不能只存无法跳转的文本名称；
- 外部信息与本人观点在视觉和文案上分区。

### 状态处理

- 攻略 ID 无效：显示“攻略不存在或已调整”并允许返回；
- 单张图片失败：显示占位，不阻断正文；
- 关联地点或路段已移除：隐藏该关联卡并记录数据错误；
- 官方资源为空：隐藏资源卡，保留统一核验提示。

### 页面验收

- 目录与章节一一对应并可定位；
- 相关地点、路段和预算工具跳转正确；
- 正文在无图片时仍连续可读；
- 不出现第三方攻略大量转载或无来源动态信息。

## 5.7 工具页（P07）

### 页面目标

提供可实际操作的软件功能，P0 通过预算计算器帮助用户估算路线成本；P1 承载路线方案和行李清单。

### 内容与组件顺序

1. 页面标题与说明；
2. **P0 预算计算器；**
3. **P1 路线方案入口；**
4. **P1 行李清单；**
5. 数据口径、更新时间和免责声明。

### P0 预算计算器输入

**路线方案：**

- 5 天：哈尔滨 → 漠河；
- 7 天：哈尔滨 → 漠河 → 满归 → 海拉尔；
- 完整路线：按本项目真实全路线。

路线的具体天数、晚数、路段和地点清单由 `BudgetRoutePlan` 配置，若真实路线与示例不同，以最终配置及页面说明为准。

**住宿标准：** 青旅、经济住宿、普通住宿。每档使用配置中的每晚参考单价。

**每日饮食：** ¥40、¥70、¥120。

首次进入采用推荐默认值：7 天路线、青旅、¥70/日，并明确显示选中状态。

### 计算公式

```text
交通费 = 所选路线包含的全部有效路段预计费用之和
住宿费 = 所选住宿档位每晚单价 × 路线住宿晚数
饮食费 = 所选每日饮食预算 × 路线旅行天数
门票费 = 所选路线包含地点的预计门票费之和
其他费 = 路线方案中配置的必要固定费用之和

基础总额 = 交通费 + 住宿费 + 饮食费 + 门票费 + 其他费
建议应急预算 = 基础总额 × 15%，四舍五入到整数元
建议携带总额 = 基础总额 + 建议应急预算
```

应急比例初始采用 15%，作为可配置常量。页面主数字展示“基础预计预算”，应急预算单独列出，不混入基础总额；同时展示建议携带总额。

### 结果区与操作

- 每次切换选项后即时重新计算；
- 展示基础总额、交通、住宿、饮食、门票、其他、应急预算和建议携带总额；
- 展示“这是基于本项目路线与参考单价的估算，不是实时报价”；
- “重置”恢复推荐默认值并提示“已恢复默认方案”；
- 若从预算攻略进入，自动定位结果区，但仍允许修改所有选项。

### 缺失费用规则

- 任一交通路段或门票费用未知时，不将其按 0 处理；
- 结果显示“已知最低预算 ¥X”，并在对应分类标注“含待补费用”；
- 存在待补费用时不展示精确的建议携带总额，只展示“至少 ¥X + 待补费用”，应急预算按已知金额计算并标注口径；
- 配置错误导致天数、晚数或单价无效时，显示“预算数据暂不可用”及重试/返回默认方案，不输出 `NaN`、负数或空结果。

### P1 行李清单

- 按证件、电子设备、衣物、防护、洗护和其他分组；
- 用户可逐项勾选，状态实时写入本地 Storage；
- 首次进入全部未勾选，并显示完成数量；
- 再次进入恢复状态；取消勾选同步保存；
- “清空已勾选”二次确认后执行；
- 存储失败时保留当前页面内状态并提示“本次状态可能无法保存”。

### P1 路线方案与收藏

- 路线方案以工具页卡片进入方案介绍区，不新增一级页面类型；可使用工具页内锚点或展开卡实现；
- 收藏入口位于地点详情和攻略详情；工具页可设置“我的收藏”分区，以地点和攻略两组展示；
- 收藏数据仅保存在本机，不登录、不跨设备同步；
- 收藏对象被删除时，打开收藏列表需过滤失效 ID，不展示空白卡片；
- 清除微信缓存后收藏和清单可能丢失，页面说明中应明确。

### 页面验收

- 三类路线、三档住宿和三档饮食均可组合并即时更新；
- 重置后准确恢复推荐默认值；
- 计算结果可通过人工样例复核；
- 缺失费用时不产生看似精确的错误总额；
- P1 本地存储失败不会导致页面崩溃或假装保存成功。

## 六、P1 行前确认与官方资源

### 6.1 模块入口

行前确认不是新一级模块，嵌入以下页面：

- 地点详情：当地公交、景区、预约和公共服务；
- 路段详情：铁路、轮渡、客运、公交等交通渠道；
- 攻略详情：与主题相关的综合官方资源；
- 攻略首页：可在 P1 上线后发布“行前确认”主题攻略。

### 6.2 资源卡内容

每张资源卡至少包含：

- 官方名称；
- 资源类型；
- 用途说明；
- 渠道类型与渠道名称；
- 可执行操作；
- 是否需要预约及建议提前天数；
- 最后核验日期；
- 风险备注。

### 6.3 渠道交互

| 渠道 | 页面操作 | 失败或受限时 |
| --- | --- | --- |
| 官方网站 | “打开网页”，使用允许的 WebView/复制链接方案 | 提供“复制链接” |
| 官方电话 | “拨打电话”与“复制号码” | 至少保留复制号码 |
| 微信公众号 | “复制公众号名称”或展示二维码 | 不制作无法直接打开的假按钮 |
| 微信小程序 | 已配置合法 AppID 时允许跳转 | 未配置时展示名称、用途和二维码/搜索说明 |
| 二维码 | 点击查看大图 | 图片失败时展示渠道名称与搜索说明 |

### 6.4 时效状态

- `已核验`：存在有效核验日期且未超过资源类型规定的复核周期；
- `建议复核`：核验日期较早，但资源仍可展示；
- `未核验`：无核验日期，只能作为线索展示；
- `可能失效`：打开失败或已知渠道调整，优先展示替代操作。

统一提示：

> 交通班次、票价、预约和开放状态可能调整，出发前请以官方最新信息为准。

## 七、数据与内容规范

### 7.1 单一数据源

- `Place`、`Visit`、`Segment`、`TripDay`、`Guide`、`Resource` 和 `BudgetRoutePlan` 为核心对象；
- 地图、行程、详情和预算工具只通过对象 ID 关联，不复制多套费用与日期；
- 路线顺序以 `Segment.displayOrder` 为准，日程顺序以 `TripDay.day` 和内部 `displayOrder` 为准；
- 重复访问同一城市通过多个 `Visit` 关联同一个 `Place`，解决哈尔滨重复经过问题。

### 7.2 展示口径

| 数据 | 存储建议 | 页面展示 | 缺失值 |
| --- | --- | --- | --- |
| 金额 | 数值，单位元 | `¥128`；预计值加“预计” | “费用待补”，不用 ¥0 |
| 距离 | 数值，单位 km | `约 350 km` 或 `350 km` | “距离待补” |
| 时长 | 分钟数 | `11 h 30 min` | “时长待补” |
| 日期时间 | ISO 日期/时间 | `2026-08-03 20:10` | “日期待补/时间待补” |
| 评分 | 1—5，0.5 步进 | `4.5 / 5` + 星级 | 隐藏该评分项 |
| 更新时间 | ISO 日期 | `最后核验：2026-08-30` | “尚未核验” |

### 7.3 历史记录与当前信息

- 本人坐过的班次、实付费用和当时体验属于历史旅行记录，必须标记旅行日期；
- 当前班次、票价、预约、开放时间属于动态信息，必须来自官方资源并标记最后核验日期；
- 预计预算是基于配置的估算，不能称为“实际花费”或“实时价格”；
- 本人观点使用第一人称；官方规则使用中性转述并注明来源用途；
- 未核实信息不得写成确定事实。

### 7.4 内容状态

统一使用：

```text
draft      草稿，仅开发环境可见
published  已发布，正式版本可见
incomplete 已发布但存在明确待补字段
archived   已归档，不在列表展示
```

## 九、功能优先级矩阵

### 9.1 P0 — MVP 必须完成

| 功能 | 页面入口 | 数据依赖 | 完成标准 |

| 完整路线地图 | 地图首页 | Place、Visit、Segment | 有效节点与路线可见，默认视野正确，失败有降级列表 |

| 攻略列表与详情 | 攻略 Tab | Guide | 已发布卡片均可打开，目录与关联跳转有效 |
| 预算计算器 | 工具 Tab/攻略 | BudgetRoutePlan、Segment、Place | 组合可选、即时计算、缺失费用不误算、可重置 |
| 全局状态与导航 | 所有页面 | 页面路由、静态数据 | 可加载、返回、重试，无明显空页和假按钮 |

### 9.2 P1 — MVP 后优先实现

| 优先级 | 功能 | 页面入口 | 数据/能力依赖 | 完成标准 |
| --- | --- | --- | --- | --- |
| P1-1 | 官方信息/行前确认 | 地点、路段、攻略详情 | Resource、复制/电话/WebView/小程序跳转 | 每个入口有用途、核验日期、可执行操作和失败替代方案 |
| P1-2 | 行李清单 | 工具页 | 本地 Storage | 勾选、恢复、取消、清空和存储失败状态完整 |
| P1-3 | 路线方案 | 工具页、预算区 | BudgetRoutePlan | 三套方案范围与成本输入一致，可驱动预算计算 |
| P1-4 | 收藏 | 地点、攻略详情；工具页汇总 | 本地 Storage | 收藏/取消/恢复有效，不要求登录和同步 |
| P1-5 | 图片全屏预览 | 各图文页面 | 微信图片预览 | 可打开、切换、关闭，失败不影响正文 |

### 9.3 P2 与明确不做

P2 仅在 P0/P1 完成且时间充足时评估：搜索、标签筛选、用户创建路线、UGC、云端收藏、AI 路线规划、天气服务、实时交通。

v1.1 明确不做：酒店或票务交易、实时导航、全国攻略、社交社区、评论私信、车票余量、实时票价、复杂用户体系和后台内容编辑器。

## 十、预算计算验算样例

正式数据补齐后必须将以下占位数替换为真实配置，并保留同类自动化或人工验算。

假设测试配置：

```text
7 天路线：6 晚
交通费合计：¥870
青旅：¥70/晚
饮食：¥50/天
门票费：¥190
其他固定费：¥0
```

预期：

```text
住宿费 = 70 × 6 = ¥420
饮食费 = 50 × 7 = ¥350
基础总额 = 870 + 420 + 350 + 190 = ¥1830
建议应急预算 = 1830 × 15% = ¥275（四舍五入）
建议携带总额 = 1830 + 275 = ¥2105
```

注意：正式可选饮食档位为 ¥40、¥70、¥120；上例 ¥50 仅用于复核 v1.0 示例总额，不作为界面选项。正式验收还需用三档实际选项各计算至少一次。

## 十一、页面级验收用例

### 11.1 首次体验与路线理解

1. 冷启动进入地图首页，5 秒内可看到产品名称和兴安岭长途旅行语义；
2. 10 秒内可识别青岛起点、主要停靠地、整体向北路线及最终返回；
3. 点击任一主要 Marker，可在 30 秒内进入地点详情并看到照片/占位、记录、费用与建议。

### 11.2 数据一致性

1. 分别从地图和行程进入同一地点，核心数据完全一致；
2. 分别从行程和地点详情进入同一路段，起终点、时间和费用一致；
3. 地图路线、行程时间轴与 `Segment.displayOrder` 一致；
4. 哈尔滨两次到访共用地点信息，但 Day、相邻路段和到访摘要分别正确。

### 11.3 特殊路线场景

1. 两个坐标接近的 Marker 不阻止用户选择目标地点；
2. 同一天含多个地点时按真实顺序展示；
3. 跨夜路线同时显示出发日、到达日和“次日到达”；
4. 换乘路线的时间线不存在倒序，等待时间可理解；
5. 地点坐标缺失时，地图其余部分仍可使用且简化列表可进入该地点。

### 11.4 预算计算器

1. 三类路线 × 三档住宿 × 三档饮食均可选择；
2. 任一选项变化后各分类和总额即时更新；
3. 默认值和重置后的值一致；
4. 使用已知测试数据手工核对基础总额、15% 应急预算和建议携带总额；
5. 任一必要费用缺失时显示最低已知预算，不把未知值按 0 计算；
6. 数据非法时不出现负数、`NaN`、无限值或空白结果。

### 11.5 内容缺失与异常

1. 无照片时有占位且正文仍可读；
2. 无评分时隐藏评分项或模块，不显示 0 星误导用户；
3. 无费用时显示待补，不显示虚假的 ¥0；
4. 无官方资源时不显示空按钮；
5. 资源过期或外链失败时有替代复制操作或核验提示；
6. 本地存储失败时清单/收藏保持当前会话状态并明确告知未成功保存；
7. 网络图片或地图失败时存在重试和核心内容降级方案。

### 11.6 按钮与闭环

- 逐页列出所有按钮，验证每个按钮存在明确结果；
- 所有返回操作回到合理入口，不丢失关键浏览位置；
- P0 正式版本不显示未实现 P1 的可点击假入口；
- 地图浏览、跟随行程、阅读攻略和计算预算四条核心路径均可完成；
- 页面不存在大面积空白、无法返回、重复跳转或明显无响应操作。

## 十二、视觉与组件方向

视觉关键词为“森林 + 铁路 + 北方 + 旅行手账”。视觉承担旅行氛围，功能承担到达方式与复刻信息。

### 12.1 组件原则

- 地图与真实照片是主要视觉锚点，日期印章、路线和车票元素作为辅助；
- 卡片保持统一圆角、间距和标题层级，不模拟传统 OTA 的商业促销界面；
- 历史记录、个人建议、官方信息使用不同标签，不能只依靠颜色区分；
- 交通方式使用统一图标体系：火车、轮渡、客运、公交、步行；
- 风险提示使用克制的警示样式，不把普通建议全部做成红色告警；
- 低保真原型阶段优先验证信息顺序、操作和状态，不要求确定最终颜色与插画。

### 12.2 推荐低保真原型清单

至少绘制以下关键画面：

1. 地图首页默认态；
2. 地图 Marker 选中与重复到访卡片；
3. 地图加载失败降级态；
4. 行程页普通日、同日多地点与跨夜路段；
5. 地点详情完整态与费用/照片缺失态；
6. 路段详情普通直达与换乘跨夜态；
7. 攻略首页与攻略详情；
8. 预算计算器默认态、计算结果和费用缺失态；
9. P1 官方资源可用/过期态；
10. P1 行李清单和收藏状态。

## 十三、开发顺序与交付检查

### 13.1 开发顺序

1. 建立核心数据对象和统一 ID 关联；
2. 地图首页 → 地点详情，跑通第一条核心路径；
3. 行程时间轴 → 路段详情，核对路线顺序与跨日逻辑；
4. 补齐真实地点、路段、费用与照片；
5. 攻略首页 → 攻略详情及关联跳转；
6. 预算路线配置 → 预算计算器；
7. 完成 P0 全局状态、异常降级和一致性验收；
8. 实现 P1 官方信息、行李清单、路线方案、收藏和图片预览；
9. 进行整体 UI 精修、真机测试与课程答辩准备。

### 13.2 P0 完成定义

- 七类页面均具备可用的完整态和必要异常态；
- 地图、行程、地点、路段使用同一套真实数据；
- 预算计算结果通过人工样例核对；
- 所有 P0 操作可点击、可返回、可重试；
- 所有真实内容的日期、费用和来源口径清楚；
- 不存在大量空页面、假数据、假按钮或明显无响应操作；
- P1 未实现内容不会阻断 P0 使用。

### 13.3 上线前内容检查

- 将全部 `【待补】` 分类为“必须补齐后发布”或“允许显示待补”；
- 核对所有照片归属与隐私信息；
- 核对路线地点坐标、顺序、Day、日期、时长和费用；
- 核对所有官方资源的用途、操作和最后核验日期；

## 十四、最终产品定义

> **《兴安岭穷游记》是一款基于真实暑假旅行经历开发的微信小程序。产品以青岛出发、途经东北城市并穿越大小兴安岭的真实旅行路线为核心，通过地图可视化和时间轴展示完整旅程，并记录各地点及路段的真实照片、交通方式、时间成本、旅行费用与个人体验。同时，产品通过主题穷游攻略、预算计算工具以及官方交通、景区预约和公共服务信息入口，为希望复刻类似路线的用户提供实际参考，降低偏远地区自由行的信息搜集成本。**

PRD v1.1 至此形成可用于低保真原型、任务拆分和开发验收的页面规格。后续内容补充和交互调整不得改变四 Tab 与七类页面边界；如确需新增一级模块，必须单独进行版本评审。
